# DSH-AUDIO-040：迁移到 DSH 0.2.1-rc.5

- Status: Done
- Date: 2026-10-30

插件的兼容基线从 DSH `0.2.0-rc.2` 升到当前 npm `latest` 的 `0.2.1-rc.5`，并在该版本上完成真实 Web 验收。

## Goal

`dsh-native-audio` 在 `0.2.1-rc.5` 上通过离线门禁，Web 中的 `read_audio`、Subagent 与 WAV 附件都能让模型听到音频，本地 Qwen3-Omni-30B 可从 Web 选用。

## Scope

In scope:
- 依赖、`engines.dsh`、测试夹具与上游契约。
- `read_audio` 跟随 `ctx.workingDirectory`。

Out of scope:
- 下游 bundle 的迁移、OpenRouter provider 路由配置、发布到 npm。

## Specs

- [bundle](../specs/bundle.md)
- [read_audio](../specs/read-audio-tool.md)

## Acceptance

- `pnpm run typecheck`、`pnpm run test`、`pnpm run build`、`git diff --check` 通过。
- 用户授权的真实 Web 验收，音频使用真实录音片段。

## Result

依赖升到 `0.2.1-rc.5`、Cordis `4.0.5`、Schemastery `3.18.5`、pi-ai `1.4.0`，移除上游已不发布的 `dsh-invariants` 与 `dsh-subagent-in-process-driver`。上游新增的 `working_directory` 工具会让 Session header 的 `cwd` 过时，所以 `read_audio` 改为 inject `workingDirectory`，并新增相对路径合同测试；测试夹具因 `startContinuable` 改名 `startActivation`、JSONL persistence 不再有默认导出、`SubagentRuntime` 需要 `workingDirectory` 而调整，这些是上游 API 变化，测试意图不变。

真实验收见 [2026-10-30 Web 验收](../research/2026-10-30-dsh-0.2.1-web-acceptance.md)：OpenRouter Qwen3.8 Omni Flash（`tool-message`）与本地 Qwen3-Omni-30B（`user-message`）通过；直连 Gemini route 没有在本版本上重新验收。
