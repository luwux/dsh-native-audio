# DSH-AUDIO-020：迁移到 DSH 0.2.0-rc.2

Status: complete

## 结果

插件的 peer 与 dev dependencies 固定为 DSH `0.2.0-rc.2`，源码、测试、文档和 pack 产物都在该基线上通过；DSH 0.2 Web 中附上的 WAV 以原生音频进入 Gemini 请求，Gemini 推理等级可以在 Web 中选择。

## Owning decision

- [0001: 原生音频作为独立 DSH 插件](../decisions/0001-standalone-dsh-plugin.md)
- [0007: DSH 0.2 用 stock 文件附件承载浏览器 WAV 输入](../decisions/0007-wav-file-attachment-ingress.md)

## 范围

1. 依赖升级到 DSH `0.2.0-rc.2`、Cordis `4.0.4`、Schemastery `3.18.4`、pi-ai `0.87.1`。
2. 消息结构：tool result 改为 `role: 'tool'` 消息；loop 请求以 system 消息携带 system prompt；只读 content；`ToolCallId`。
3. Provider 配置改为 Loader volatile Config，entry id 与旧 settings section 同名以便导入。
4. Gemini 推理等级映射到 `thinkingLevel`，默认请求思考摘要。
5. 删除 browser module、Typert Remote 与 Web submit service，新增 `file-ingress`。
6. 测试迁移到 0.2 API，并覆盖 Subagent 调用 `read_audio` 与 WAV 文件附件转换。

## 非目标

- 不迁移下游 bundle。
- 不提供音频播放器或 AudioBlock 专用 history renderer。
- 不保留 DSH `0.1.1-rc.2` 兼容。

## 验收标准

- `pnpm run typecheck`、`pnpm run test`、`pnpm run build`、`python3 -B scripts/verify_agent_notes.py`、`git diff --check` 通过。
- pack tarball 安装进 DSH `0.2.0-rc.2` Web profile 后启动无插件错误，模型菜单列出 Gemini 与 OpenRouter 音频 route，Gemini 3.8 Flash 显示推理等级。

## 验证

- 2026-10-08 全量离线门禁见 [2026-10-08 门禁记录](../research/2026-10-08-dsh-0.2-offline-gate.md)：typecheck、20 个测试文件 69 个测试、build、pack、Agent Note 检查与 `git diff --check` 全部通过。
- Pack tarball 经 `dsh plugin --profile web add` 安装进 DSH `0.2.0-rc.2` 的 Web profile；`dsh web --dump-config` 显示五个 entry，启动后服务日志没有插件错误。旧 `settings.yaml` 的 `llm-google-gemini-audio` section 导入同名 entry。Web 模型菜单列出 Gemini 3.8 Flash、Gemini 3.1 Pro 与 OpenRouter 音频 route；Gemini 3.8 Flash 的推理等级为 Default、Minimal、Low、Medium、High，Gemini 3.1 Pro 为 Default、Low、Medium、High。
- 未发送消息，未调用任何 provider。真实 Gemini 听取验收需要用户另行授权。

## 已知风险

- 含 AudioBlock 的 DSH `0.1.1-rc.2` Session 无法在 0.2 打开（DSH v2→v3 Session 格式迁移的限制），旧 Session 只能在 0.1.1 环境中查看。
- `gemini-3.1-pro-preview` 的 `thinkingLevels` 写在用户 profile 中，取值未经 provider 验证。
