# 2026-10-30：DSH 0.2.1-rc.5 的 Web 验收

本记录是 [DSH-AUDIO-040](../tasks/2026-10-30-dsh-0.2.1-migration.md) 的真实验收证据。被测代码是迁移到 `0.2.1-rc.5` 后打包的 tgz（改动在提交 `c1b020c` 之后），宿主是 npm 安装的 `@deepseek-ai/dsh@0.2.1-rc.5` Web，解析到 `pi-ai@1.4.0`；工作区是一个存放真实录音片段的本地目录，访问模式“工作区内修改”。所有请求都由 Web 会话发出，用户在会话中授权了真实请求与启动本地模型。

## 测试设计

音频是工作区中的真实录音片段（16 kHz 单声道，约 10 秒），文件名只是编号。模型只被要求描述声音与场景；回答结束后才与参考描述对照，参考描述本身也可能不全。本轮没有重复不听音频的对照，对照见 [2026-10-14 验收](2026-10-14-chat-completions-web-acceptance.md)。

## 结果

| 路径 | 片段 | 模型回答要点 | 判定 |
| --- | --- | --- | --- |
| OpenRouter `qwen/qwen3.8-omni-flash`，`tool-message`，Main `read_audio` | 039 | 低沉电机嗡嗡，随后高速旋转啸叫，再回落停止；像电动工具 | 相符，没有判断出具体机器 |
| 同上，Subagent 自己 `read_audio` 后 `send_message` | 063 | 一句人声，接密集高频吱叫与低沉咕噜声；像人对小宠物录音 | 部分相符，说话人性别判断错误 |
| 本地 llama-server `qwen3-omni-30b-a3b-instruct-bf16`，`user-message`，Main `read_audio` | 037 | 类似昆虫的重复鸣叫，伴随有人在户外说话与挖掘 | 相符 |
| 同上，Subagent | 137 | 连续高速的机枪射击声 | 不相符，听到了连续爆发声，声源判断错误 |
| 同上，Web 输入框附加 WAV，不调用工具 | 038 | 模糊男声，背景持续键盘敲击声 | 部分相符，人声相符，背景声来源判断错误 |

Session log 中 Subagent 用例由 child 自己调用 `read_audio`；附加 WAV 的 `user/message` 同时含 `file` 与 `audio` 块。本地模型的后续请求只重新计算约 280 个 token，说明前缀缓存没有被打断。

直连 Gemini route 没有在本版本上重新验收，只有离线合同测试。

## 其他观察

含 AudioBlock 的 DSH 0.1.1 旧 Session 仍然无法打开（`failed to observe session ... format v2 tool/result`），页面打开这种 Session 时模型选择器停在“正在加载模型…”，新建会话后正常。

## 局限

每条路径只跑一次，判定是人工对照自由文本。OpenRouter 上丢弃音频的 provider 问题未重测。
